1. What is actually failing?

The most important finding is that your repository describes the product as a browser-only simulation, not a functioning cryptocurrency exchange. The app’s own documentation explicitly states that it has no authentication, connected exchange, blockchain, custody provider, or production database integration.

I could reach the deployed URL, but the web inspection tool did not expose its rendered page content. Therefore, I cannot honestly claim to have reproduced every live UI error or verified every interaction in a real browser. The findings below distinguish confirmed architectural limitations from issues that still require testing.

Priority failure list

1. Wallet is not a real wallet

Critical

Sending, receiving, and balances are simulated locally. The recipient field is not connected to a blockchain, and the receive identifier is explicitly non-routable.

Evidence: artifacts/cks-demo/src/pages/wallet.tsx

2. No persistent user accounts

Critical

Portfolio state is saved in browser localStorage. There is no implemented account system that synchronizes balances and transactions across devices or protects individual user data on a server.

Evidence: artifacts/cks-demo/src/lib/demo-store.tsx

3. Prices and performance are illustrative

High

Market prices, price changes, and portfolio charts use predefined demo values. They should not be presented as live market data.

Evidence: artifacts/cks-demo/src/lib/demo-store.tsx and dashboard.tsx

4. Digital card is a concept, not an issued card

High

The current app includes a card-preview experience, but that alone does not provide card issuance, authorization, settlement, or a connection to a payment network.

5. No production financial security layer

Critical

The demo’s local state is not an authoritative financial ledger. Real money operations require server-side authorization, validated transactions, secure key management, provider integrations, and reconciliation.
